# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An empirical security study: how much of a NeRF's training data must be
poisoned (via masked compositing) to suppress a target object, and what
collateral damage that causes to the rest of the scene. This is a research
project with a locked experimental protocol, not a conventional software
project — **the repo's docs are the source of truth for what is and isn't
allowed**, and violating them invalidates results, not just style.

**Current state: pre-code scaffold (Phase 0 of `docs/ROADMAP.md`).** Only
docs and configs exist so far — `src/`, `scripts/`, `data/`, `experiments/`,
and `tests/` described below are the planned layout from
`docs/PROJECT_STRUCTURE.md`, not yet created. Check `docs/ROADMAP.md`'s
status tracker at the top before assuming any phase's deliverables exist.

## Non-negotiable rules (violating these invalidates results)

- **Every hyperparameter or condition lives in a `configs/*.yaml` file**,
  never hardcoded in `src/` or `scripts/`. A script's only required
  argument is a config path.
- **Poisoned images are only ever produced by `src/poisoning/compositor.py`**
  from the fixed formulas in `METHODOLOGY.md` §3 — no hand-editing, no
  per-image judgment calls.
- **The poisoning budget is % of `V_target` (target-visible views), not %
  of all training views** — see `METHODOLOGY.md` §2 / `DECISION_LOG.md`
  D-002. This is the independent variable; don't redefine it casually.
- **`data/blender_scenes/eval_holdout/` is frozen after Phase 4** — nothing
  in `src/` or `scripts/` writes to it, and no metric is ever computed
  against anything else.
- **Every training run needs an `experiments/logs/<run_id>.md` entry**
  (from `docs/templates/EXPERIMENT_LOG_TEMPLATE.md`) before its metrics can
  go into `experiments/results/results.csv`, which is append-only and
  machine-generated by `scripts/evaluate.py`.
- **`notebooks/` is scratch-only** — nothing there produces a number that
  goes in the paper; promote reused logic into `src/` or `scripts/`.
- Seeds (model init + random-view-selection) are fixed in the config
  *before* training, never chosen after seeing results. Minimum N=3 seeds
  per condition (`DECISION_LOG.md` D-007).

## Architecture (planned — see `docs/PROJECT_STRUCTURE.md` for full detail)

- `src/nerf/` — vanilla NeRF model/training (pure PyTorch, no custom CUDA
  extensions — deliberate choice, `DECISION_LOG.md` D-005, to avoid sm_120
  build issues with tiny-cuda-nn/Nerfstudio on the dev GPU).
- `src/poisoning/compositor.py` — implements the two attack formulas
  (hard erasure, soft suppression) as pure pixel arithmetic over
  Blender-rendered `original`/`background_plate`/`mask` triples.
- `src/poisoning/view_selection.py` — random vs. strategic view sampling
  from `V_target`.
- `src/data_pipeline/` — Blender render orchestration, dataset/manifest
  builders.
- `src/metrics/` — masked/unmasked PSNR/SSIM/LPIPS.
- `scripts/*.py` — thin CLI entry points only (`render_scene.py`,
  `build_poison_set.py`, `train.py`, `evaluate.py`); no logic lives here,
  it calls into `src/`.
- Data flow: `data/raw/*.blend` (Windows, hand-built) → headless Blender
  render → `data/blender_scenes/` + `data/masks/` + `data/background_plates/`
  → `build_poison_set.py` reads a `configs/poisoning/*.yaml` condition →
  `data/poisoned/<condition_id>/` + `MANIFEST.csv` → `train.py` → checkpoint
  → `evaluate.py` against the frozen `eval_holdout/` → `experiments/results/results.csv`.

## Environment

Split local/cloud setup, detailed in `environment/SETUP.md`:

- **Local (WSL2 Ubuntu, RTX 5060 laptop / Blackwell sm_120):** dev,
  debugging, small runs. Requires PyTorch cu128+ wheels explicitly
  (`pip install torch --index-url https://download.pytorch.org/whl/cu128`)
  — unpinned installs risk silently falling back to an unsupported kernel
  path. Verify with the compute-capability check script in `SETUP.md` §1.4
  before writing research code.
- **Cloud (Colab/Kaggle):** bulk of the Phase 6 training sweep.
  `requirements.txt` must mirror `environment/environment.yml` exactly —
  update both in the same commit.
- **Blender:** native Windows install (not WSL2/WSLg — see `DECISION_LOG.md`
  D-008), Cycles device set to OptiX. Headless dataset rendering:
  `blender.exe --background scene.blend --python scripts/render_scene.py`.
  Bridge Windows-rendered output into the WSL2 repo via either a UNC path
  or an explicit rsync/robocopy step — pick one and don't mix.

This project uses `uv` (`pyproject.toml` + `uv.lock`), Python 3.12
(`.python-version`), with a private PyTorch index (`cu130` wheels) declared
in `pyproject.toml`.

## Commands

No build/lint/test tooling exists yet (Phase 0 in progress — see
`docs/ROADMAP.md` Phase 0 tasks). Once `scripts/` and `tests/` exist per
`docs/PROJECT_STRUCTURE.md`, the expected shape (per the roadmap) is:

- Train: `python scripts/train.py <config_path>`
- Evaluate: `python scripts/evaluate.py <config_path>`
- Build a poisoned set: `python scripts/build_poison_set.py <condition_config_path>`
- Full sweep: `scripts/run_sweep.sh` (loops train+evaluate over `configs/poisoning/*`)
- Unit tests live under `tests/` (compositor, metrics, view selection) —
  no test runner is configured yet.

Don't invent commands beyond what's documented here or in the roadmap;
check `docs/ROADMAP.md`'s current phase before assuming a script exists.
